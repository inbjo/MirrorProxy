# MirrorProxy 1.3.2

MirrorProxy 1.3.2 是一次以可观测性、构建稳定性和管理体验为重点的维护版本。
它补齐了 1.3.1 自定义软件仓库的健康检测链路，同时解决 GeoIP 发布构建和前端依赖审计问题。

## 主要更新

### 自定义软件源现在会参与健康检测

- 管理员通过 `upstreams.additional_os` 添加的软件仓库，现在会和内置源一起参与启动后的自动检测、每 15 分钟定时检测以及后台“立即检测”。
- 健康页面会显示自定义源的可用状态、HTTP 状态码、检测延迟、检测时间和具体上游地址。
- 自定义源会正确计入可用、异常、未启用和未检测数量；删除源后，旧的检测结果不会继续残留在报表中。
- 当 `os` 代理未启用时，自定义软件源会明确显示为“未启用”。

检测使用管理员配置的仓库根地址，不会修改客户端的发行版代号、组件或签名密钥设置。

### GeoIP 发布构建更加稳定

- 修复 Release 构建下载最新 GeoIP 数据后因旧 SHA-256 不匹配而失败的问题。
- 构建脚本现在固定到经过验证的 ip2region 上游提交，并使用与该提交对应的 IPv4、IPv6 文件校验值。
- 上游 `master` 后续更新不会再导致同一版本的发布构建随机失败；需要升级数据时会显式更新提交号和校验值。
- Web 专用设计变量文件已归入 `web/src`，Docker 与普通前端构建现在使用同一份目录上下文，并通过静态检查防止再次漂移。
- 真实客户端 smoke 不再使用固定监听端口，而是由操作系统动态分配空闲端口，避免与 Runner 上的并发进程冲突。

### 管理后台与移动端体验

- 公共页面、用户账户和管理后台已针对 320、375、414、768 像素宽度重新检查和优化，避免页面级横向溢出。
- 桌面端管理区域获得更合理的内容宽度，密集配置项不再被过度压缩。
- 管理标签使用更紧凑的可见名称，并在窄屏保留清晰可见、可拖动的横向滚动条。
- 缓存清理、用户删除、会话撤销、Passkey 删除、登录方式解绑、专属地址更换、自定义源删除等敏感操作，统一改为站内确认对话框，不再依赖浏览器原生弹窗。
- 改善删除按钮点击区域、配置表单布局、提示信息和中英文一致性。

### 依赖安全

- 将 `jsdom` 使用的传递依赖 `undici` 更新到安全兼容版本。
- 将 `postcss` 使用的传递依赖 `nanoid` 从 3.3.16 更新到 3.3.18，修复自定义生成器在长度为零时可能无限循环的问题。
- 两项修复均为锁文件级兼容更新，没有强制升级 Vite、React 或其他主要框架。
- 官方 npm registry 审计结果为 `0 vulnerabilities`。

### 文档整理

- 重写中英文 README 的产品介绍，突出自部署镜像入口、上游故障切换、按需缓存、跨平台改源、团队配额、健康检测和流量统计等实际价值。
- 补充按生态分类的软件源支持范围和部署后的能力说明。
- 移除已经完成的早期实施计划，后续工作统一通过 GitHub Issues、Milestones 和 Release Notes 跟踪。

## 兼容性

- 原有代理路由、配置字段、SQLite 数据和 `additional_os` 配置无需迁移。
- 自定义仓库继续使用 `/os/<源名称>/...` 代理路径。
- 本版本没有新增必须启用的配置项，也没有改变默认访问控制策略。

## 验证

- GitHub CI 全部通过，包括 Rust 测试、Clippy、格式检查、浏览器端到端测试、真实客户端协议 smoke、跨平台客户端测试、依赖审计和覆盖率任务。
- 本地验证通过 Rust 工作区测试、前端 15 项单元测试、生产构建以及官方 npm 安全审计。
- GeoIP IPv4、IPv6 数据已从固定提交重新下载并通过 SHA-256 校验；`x86_64-unknown-linux-musl` 服务端 Release 构建通过。
