# MirrorProxy v1.7.2

MirrorProxy v1.7.2 fixes traffic reservation settlement, makes exhausted quotas clearer, and improves administration, installation diagnostics and Release downloads.

## Highlights

- Settle streamed traffic when a client cancels a request. Preserve the original reservation month, user, group and accounting state when configuration or membership changes during a request.
- Keep global reservation tracking symmetric even when the global cap is disabled. Settling an older request can no longer release bytes reserved by a different active request after a quota configuration change.
- Show Chinese and English public notices when monthly traffic is exhausted, explaining the reset schedule and how to contact the administrator.
- Refine administration overview spacing, show an explicit empty state for daily statistics, and format traffic-chart tooltip values as readable byte units.
- Explain network, TLS and missing-asset failures in Unix and PowerShell installers. Make explicit that proxying the installer script alone does not proxy subsequent downloads; use the mirror option for those downloads.
- Organize Release assets into platform, architecture and package tables with checksum links.

## Security and dependency status

The frontend toolchain updates the Hono Node server adapter to 2.1.3 and modern glob/minimatch consumers to patched versions. Authentication, authorization, CSRF, SSRF, TLS and quota enforcement remain enabled.

Dependency audits retain the scoped exceptions documented in [SECURITY.md](https://github.com/inbjo/MirrorProxy/blob/v1.7.2/SECURITY.md): RUSTSEC-2023-0071 and RUSTSEC-2026-0387 affect private/secret operations outside the reviewed OIDC public-key verification path; the low-severity deepmerge exception is unchanged. The legacy Umi checker still needs minimatch 3.1.5's callable CommonJS API. Its GHSA-g3hv-75wg-m249 exception is restricted by advisory, severity, dependency path and checker version, including propagated findings. This is an accepted build-tool risk, not a patched dependency or an exception-free audit. Other findings still fail the gate.

## Compatibility, upgrade and rollback

Existing configuration, routes, CLI setup output and SQLite data remain compatible. No manual database migration or configuration change is required.

Download the artifact matching your operating system and architecture, verify its published SHA-256 checksum, and preserve configuration, database, cache and GeoIP files before replacing the executable. Restart the service and verify its version and representative proxy requests. To roll back, restore the previous executable and restart with the preserved configuration and data.

Publishing this release does not replace an existing production installation.

## Verification

Release gates cover locked Rust formatting, Clippy and tests; frontend unit/toolchain tests, build and Chromium browser tests; release-table generation; dependency audits with the documented exceptions; real administration sessions and protocol smoke tests. Consult the CI and CodeQL runs for the exact release commit for results. Published artifact verification checks SHA256SUMS and the unpacked executable's version.
