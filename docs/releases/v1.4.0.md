# MirrorProxy 1.4.0

MirrorProxy 1.4.0 expands container-registry coverage, strengthens real-client
verification, and fixes encrypted runtime configuration handling reported in
GitHub Issue #6.

## Highlights

### More public container registries

- Added public-image proxy support for GitLab Container Registry
  (`registry.gitlab.com`), NVIDIA NGC Catalog (`nvcr.io`), and Oracle Container
  Registry (`container-registry.oracle.com`).
- The catalog, server routing, runtime configuration, administration console,
  tests, and example configuration expose the three registries consistently.
- CI now performs a real OCI distribution flow for each new registry: fetch a
  manifest, select the `linux/amd64` child where needed, download its config
  blob, and verify the advertised SHA-256 digest.
- This release deliberately supports public projects only. Private-project
  credentials for these three registries are not accepted or persisted.

The earlier registry expansion in this release also covers GCR, Microsoft
Artifact Registry, Elastic Registry, Kubernetes Registry, Quay, GitHub
Container Registry, and Red Hat Registry.

### Encrypted configuration fix

- Fixed administrator username changes failing when runtime configuration is
  encrypted with `MIRRORPROXY_MASTER_KEY`.
- Runtime configuration is now decrypted before updating the WebAuthn
  break-glass username and encrypted again before the transaction is committed.
- Added regression tests for both related and unrelated break-glass accounts;
  encrypted values remain encrypted at rest.

Thanks to the reporter of [GitHub Issue #6](https://github.com/inbjo/MirrorProxy/issues/6)
for the clear reproduction details.

### Compatibility, security, and CI

- Improved Go module, npm, and OCI request compatibility for additional native
  client behavior.
- Updated `h2` with upstream empty-frame resource-limit fixes.
- Updated GitHub Actions and CodeQL configuration to supported runtimes and
  restored warning-free Clippy validation on Rust 1.98.
- Extended the bilingual Wiki with dedicated Docker Engine/Desktop,
  containerd/K3s, NAS, panel, rollback, and troubleshooting guides.

## Compatibility

- Existing proxy routes, TOML fields, SQLite databases, and public registry
  configuration remain compatible.
- No database migration or newly required setting is introduced.
- GitLab, NVCR, and Oracle support is anonymous/public-only in 1.4.0; private
  projects continue to require direct registry access.

## Verification

- Rust workspace formatting, tests, and Clippy with all targets and features.
- Frontend unit tests, production build, and Playwright end-to-end tests.
- Real anonymous OCI pulls through MirrorProxy for GitLab, NVCR, and Oracle,
  including config-blob digest validation.
- GitHub CI, CodeQL, dependency audit, cross-platform client, and release checks
  are expected to pass before the `v1.4.0` tag is created.
