# MirrorProxy 1.3.0

MirrorProxy 1.3.0 focuses on predictable proxy behavior, safer single-instance
operations, and production-ready client distribution. It deliberately does not
add multi-instance clustering or high availability.

## Highlights

### Reliable caching and upstream routing

- Added a bounded on-disk cache with upstream `Cache-Control` support,
  `Vary` handling, ETag/Last-Modified revalidation, configurable TTL limits,
  capacity-based eviction, live statistics, and an audited purge operation.
- Restricted automatic fallback to transport failures and explicitly retryable
  HTTP responses, avoiding accidental fallback on authentication and other
  meaningful upstream responses.
- Added optional adaptive upstream selection. Repeated failures open a circuit,
  while healthy candidates are ranked using observed latency. Existing
  installations remain in deterministic ordered mode unless this is enabled.
- Changed request limiting from one process-wide queue to independent user or
  client-IP windows. Health and control endpoints are excluded.

### Security and administration

- Added durable administrator lockout and per-user/per-source login throttling
  to reduce password brute-force attempts without hiding the public admin URL.
- `/metrics` is now restricted to local requests by default. Remote scraping
  requires an explicit `metrics.local_only = false` configuration and suitable
  network protection.
- Added versioned SQLite schema tracking, integrity checks, `doctor`, consistent
  `backup`, and guarded `restore` operations.
- Added optional XChaCha20-Poly1305 encryption for sensitive SQLite values via a
  stable 32-byte `MIRRORPROXY_MASTER_KEY`. Existing deployments remain readable
  when the key is not configured, but stored secrets are not encrypted at rest.
- Added per-team mirror-target allowlists. Existing teams retain open access
  until an allowlist is configured.
- Added an optional private management listener while keeping the normal public
  administration entry available.

### Alerts and site identity

- Added quota and upstream-health alerts through generic webhooks and SMTP
  email, including localized event context and bounded retry behavior.
- Added server-rendered site title, SEO description, SEO keywords, favicon URL,
  and footer copy settings so browsers, crawlers, and link previews receive the
  configured metadata directly in the initial HTML.
- Corrected the native HTTPS checkbox layout, cache purge button, upstream
  strategy selector styling, and Chinese translations for strategy values.

### Client distribution

- Published standalone `mirrorproxy` clients for Windows x64, macOS Intel,
  macOS Apple Silicon, Linux x64, and Linux ARM64.
- Added Homebrew Tap publication and a signed APT repository with independent
  `amd64` and `arm64` client packages.
- Added WinGet multi-file manifests for the portable Windows ZIP. The first
  version must be accepted into `microsoft/winget-pkgs`; later releases can
  submit automated update pull requests.
- Retained server archives and native DEB/RPM packages as separate
  `mirrorproxy-server` artifacts.
- Added SHA-256 checksums, cross-platform client tests, dependency audits, Rust
  coverage, browser E2E tests, and real server/administrator smoke tests.

## Compatibility

- Existing proxy routes, ordered upstream selection, and team access defaults
  are preserved.
- Cache, adaptive selection, private management listener, database encryption,
  and alert delivery remain opt-in where enabling them changes runtime behavior.
- Multi-instance clustering and high availability remain outside the 1.3.0
  scope.

## Upgrade checklist

1. Stop the service and run `mirrorproxy-server --config config.toml backup backup.sqlite3`.
2. Configure a stable 32-byte `MIRRORPROXY_MASTER_KEY` before the first 1.3
   start if database secret encryption is desired. Back up this key separately.
3. Start 1.3.0 and run `mirrorproxy-server --config config.toml doctor --json`.
4. Verify one proxy target, `/healthz`, administrator login, source health, and
   cache status. The public administration entry remains available;
   `management.enabled` adds an optional private entry.
5. Review webhook/email alerts, site title/SEO/favicon/footer copy, cache TTL, upstream
   selection, and team target-access defaults.

Existing installations remain in ordered upstream mode, retain open team target
access until an allowlist is configured, and keep the management listener and
webhook alerts disabled until explicitly enabled. Remote `/metrics` access is
disabled by default; set `metrics.local_only = false` only when the surrounding
network policy protects it.
