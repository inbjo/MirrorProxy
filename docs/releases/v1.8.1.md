# MirrorProxy v1.8.1

v1.8.1 makes advanced settings easier to navigate, clarifies client proxy addresses, and simplifies source setup for native package managers.

## Administration

- Advanced settings use tabs with independent saves. When leaving an edited tab, administrators can save, keep the draft for later, or stay on the tab.
- The mirror source table labels built-in proxies, fixed system repositories, removable repositories, and internal upstreams. Client proxy addresses can be copied separately from upstream URLs. The editor accepts one HTTP(S) URL per line or comma-separated input and preserves the configured order.
- Administrators can add custom repositories in the same table and can enable or disable the WinGet adapter from the console.
- Page theme and navigation layout preferences are saved in the current browser.
- These changes address [Issue #17](https://github.com/inbjo/MirrorProxy/issues/17) in [PR #18](https://github.com/inbjo/MirrorProxy/pull/18).

## Client setup and updates

- Use distribution-specific commands such as `mirrorproxy set debian`, or let `mirrorproxy set system` detect the system. The client can reuse the MirrorProxy instance selected at installation or saved with `mirrorproxy use`.
- Supported short source commands merge changes into existing configuration and retain rollback support. Manual instructions use persistent settings where the package manager supports them. npm explicitly uses its global configuration, and Poetry download sources remain project-specific.
- Run `mirrorproxy update --check` to check for a stable release and `mirrorproxy update` to update standalone installations. Interactive update notices only report available versions. Use the original package manager to update managed installs.

## Security and compatibility

- Update the Rust URL parser to 2.5.9 to address [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592.html), a process-aborting stack overflow in origin calculation.
- Update the SMTP dependency and retain the existing administrator authentication, configuration revision checks, and API and SQLite compatibility.
- Windows x64 and ARM64 client and server archives use static MSVC runtime linkage.

## Upgrade and rollback

Verify the appropriate artifact with `SHA256SUMS` before installing. For a server upgrade, back up the configuration and SQLite data, replace the binary, restart the service, and verify `--version`, `/healthz`, and representative proxy routes. Restore the previous binary and the pre-upgrade backup if rollback is needed.

## Verification

The release checks cover locked Rust tests and dependency auditing, Chromium end-to-end and real administration browser smoke tests, native client compatibility, CodeQL, and Windows PE architecture and runtime imports. Linux CI reuses the same checksum-verified binaries for server and public client protocol smoke tests.
