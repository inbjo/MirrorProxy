# MirrorProxy v1.8.0

v1.8.0 adds an opt-in DNS-over-HTTPS relay, makes runtime settings safer to change, and improves administrator form and audit behavior.

## DNS over HTTPS

- Enable the RFC 8484 `/dns-query` endpoint in administration settings. It accepts DNS wire messages over GET and POST and supports configurable HTTPS resolvers, health probes, and bounded retries.
- A bounded in-memory TTL cache coalesces identical concurrent queries. The default ECS mode preserves client-supplied ECS without adding identifying metadata. The optional auto mode derives a public client subnet through the configured proxy trust boundary.
- DNS requests have an independent per-client rate limit. IP access, user-subdomain, and team target policies apply. DNS traffic is exempt from download quotas and persistent traffic billing.
- The public console shows the setup guide when DoH is enabled. Administrators can inspect upstream health and request telemetry.

## Runtime configuration and administration

- A request uses a consistent runtime configuration snapshot. Conditional saves reject stale revisions while preserving the administrator's draft. Background cache maintenance and graceful shutdown improve handling of active requests.
- Access & quotas, Advanced, and Administrators & security place the configuration save below the form. Contextual help is available next to the relevant headings.
- Successful administrator Passkey sign-ins resolve the client address through the same trusted proxy chain as password sign-ins. Existing audit entries keep their recorded values.

## Security and dependencies

- Bundle SQLite 3.54.1 through the pinned SQLx compatibility update to address the SQLite WAL issue. Update Hono and the Hono Node adapter in the frontend toolchain, and update the locked QUIC dependencies.
- The temporary exception for [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) covers only the reviewed picomatch build-tool paths and versions. Raw npm audit still reports the vulnerability. See [SECURITY.md](https://github.com/inbjo/MirrorProxy/blob/v1.8.0/SECURITY.md) for its scope and removal criteria.

## Upgrade and rollback

DoH is disabled by default. Existing installations can retain their configuration and SQLite schema. Review the `[doh]` settings and trusted proxy list before enabling the relay. Windows x64 and ARM64 client and server packages continue to use static MSVC runtime linkage. macOS packages contain the client.

Back up the configuration and SQLite data before replacing an existing server. Verify the matching artifact against `SHA256SUMS`, then verify `--version` and representative routes after restarting. To roll back, restore the previous binary and the pre-upgrade configuration and database backup as needed.

## Verification

Release checks cover locked workspace and browser tests, the administration and DoH protocol paths, dependency audits, and CodeQL. Windows x64 and ARM64 client and server packages are checked for architecture and normal and delay-loaded CRT/OpenSSL imports. Published downloads include the SHA-256 manifest.
