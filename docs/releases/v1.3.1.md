# MirrorProxy 1.3.1

MirrorProxy 1.3.1 completes the custom public repository workflow requested in
Issue #5. Administrators can add, rename, edit, and remove public APT or static
file upstreams without adding a new compiled adapter for every repository.

## Highlights

### Administrator-managed repositories

- The administration console now provides complete CRUD for
  `upstreams.additional_os`.
- Source names are normalized and validated as safe URL path segments.
  Duplicate names and collisions with built-in OS repository routes are
  rejected before saving.
- Upstream roots must be valid HTTP or HTTPS URLs.
- Every row shows the resulting proxy repository URL and uses consistent
  columns across repositories with different URL lengths.

For example:

```text
clickhouse-deb
https://packages.clickhouse.com/deb
https://mirror.example/os/clickhouse-deb/

docker-ce-debian
https://download.docker.com/linux/debian
https://mirror.example/os/docker-ce-debian/
```

### Public source catalog

- `/api/sources` now merges custom repositories from the active runtime
  configuration with the built-in catalog.
- Saved custom repositories appear under the public Software repositories
  category and expose their MirrorProxy repository URL.
- The custom repository dialog no longer generates unsupported MirrorProxy CLI
  commands or claims to configure a local client. It tells users to replace the
  upstream repository root while preserving distribution suites, components,
  signing keys, and other client-owned settings.

## Compatibility and scope

- Existing `/os/<source-name>/...` routes and all built-in adapters are
  unchanged.
- Existing `additional_os` entries continue to load without migration.
- This release proxies public repositories and static files. It does not add
  artifact upload, hosted repositories, or an unrestricted open proxy.

## Validation

The production `sina.dev` instance was validated locally against both custom
APT repositories. MirrorProxy returned each repository's signed InRelease and
Packages index, then streamed a real `.deb` whose size and SHA-256 matched the
published package metadata.
